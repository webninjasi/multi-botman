# 2026-11-04 12:00 — `/apply APP` lifecycle command

## Problem

No command applied env or Compose edits:

- `/restart` runs `compose restart`, which keeps the existing container, so it keeps the old env and Compose config.
- `/update` returns early as a no-op when `current` already points at the fetched SHA, so it never reaches `up`.
- `/env ...` and `/config compose upload` only write files, by design.

The only workaround was SSH plus a manual `compose up -d`, or a dummy commit.

## Change

- New `apply` lifecycle operation, hybrid `/apply APP` / `!apply APP`. It runs `compose up -d --no-deps <service>` (180s timeout) under the stack lock, with the same channel authorization and config reload as start/stop/restart/status (`src/botman/compose.py`, `src/botman/commands/lifecycle.py`).
- Compose recreates the container only when its config changed, so running `/apply` with nothing changed is harmless.
- It does not build. It uses the image of the active release, so new code still goes through `/update`.
- `/env upload|set|unset` and `/config compose upload` replies now point to `/apply`.

- `test_discord_lifecycle.py`: `apply` is registered.
